# 把话讲明白 · clear-explanations

**简体中文** | [English](README.en.md)

**让 AI 把话说清楚，让你更容易听懂。**

你有没有遇到过：AI 写了很长一段，你看完还是不知道它到底想说什么；追问一句“能不能讲明白一点”，它又换了几个词，把同样的话说了一遍。

这个 Skill 就是为这样的时刻做的。你可以让 AI 一开始就用它回答，也可以在没听懂时用它重新解释。不管是在学新东西、讨论工作，还是请 AI 帮你想办法，都可以试试。

## 比如，你想做一份销售分析

下面用一个日常工作中的提问，示意两种讲法。

**你问：“老板让我分析这个月的销售情况，我应该先看什么？”**

你可能会得到这样的回答：

> 建议从销售规模、增长趋势、产品结构、客户分层和渠道表现等维度展开，结合同比、环比识别异常，进一步下钻分析。

这些方向都有道理，可你可能还是不知道第一步该做什么，以及为什么要这么做。

换一种讲法：

> 这份分析先回答一个核心问题：**这个月销售是增长了还是下降了，变化主要来自哪里，原因是什么？**
>
> 可以按四步来做：
>
> 1. **看整体：变化有多大？** 对比本月和上月的销售额；如果有明显的淡旺季，再和去年同月比，避免把季节变化误当成经营出了问题。
> 2. **找位置：哪里变化最大？** 按产品、门店或渠道拆开看，找出哪些部分贡献了主要增长，或造成了主要下降，把排查范围缩小。
> 3. **查原因：是卖得多了，还是价格变了？** 针对变化最大的部分，先看销量和实际成交价格，再结合促销、缺货等具体情况核实原因。数据能帮你找到线索，但不能仅凭同时发生就认定因果。
> 4. **给结论：接下来关注什么？** 说清整体变化、主要来自哪里、哪些原因已确认，再提出有依据的建议；还没查清的，列出需要补充的信息。
>
> 如果老板真正关心的是“卖得更多，为什么反而没赚到钱”，就要把成本和利润也纳入分析，调整这条路径。

先知道要回答什么，再沿着“看整体 → 找位置 → 查原因 → 给结论”往下走，每一步都有目的，也知道什么时候需要调整方向。

*这是为说明讲法编写的例子，不是真实对话记录。*

## 什么时候可以用

- AI 解释了一个概念，你还是不明白它是什么意思。
- AI 给了很多分析，你想先弄清楚最重要的是什么。
- AI 建议你这样做，你想知道为什么，以及是否适合自己的情况。
- 你已经说了“没懂”，想让它换个角度讲，而不是再重复一遍。

它不要求每次都长篇解释。简单问题直接答；你想简短一点、详细一点，或者从例子讲起，都可以直接说。

## 下载与使用

在仓库页面选择 **Code → Download ZIP**，解压后将文件夹命名为 `clear-explanations`。也可以只把 [SKILL.md](SKILL.md) 保存到同名文件夹里。

**在 Codex 中：** 将文件夹放入 Skills 目录，默认路径为：

```text
~/.codex/skills/clear-explanations/SKILL.md
```

若设置了 `CODEX_HOME`，使用其下的 `skills/`。已有同名文件时，先比较或备份。

安装后，在下一轮对话中输入：

```text
$clear-explanations 请给我讲讲：[你的问题]
```

也可以接着已有对话说：

```text
$clear-explanations 这里我没懂，能不能换个例子讲？
```

执行指引目前为中文，无脚本，不需要额外 API 密钥。其他 AI 工具的安装方式请以各自说明为准；也可以尝试把 `SKILL.md` 正文作为对话指引使用。

## 为什么做这个

我在和 AI 一起写代码、做产品时，经常遇到这种情况：它解释了很多，我却还是不知道为什么要这么做，或者接下来该干什么。有时我只是卡在其中一步，它却又从头讲了一遍。

于是，我把自己希望它怎样回答、没听懂时怎样重新解释，整理成了这个 Skill。它会随着使用中发现的问题持续改进，也欢迎你通过 Issues 告诉我：哪句话没听懂，或者怎样讲会更好理解。

讲得明白，内容也可能有错；重要的事实和结论仍需核实。
